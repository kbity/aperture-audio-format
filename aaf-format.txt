Aperture Audio Format (c) 1986 Aperture Science

This document describes the usage of the aaf file format (.aaf/.aaff).
The AAF Format uses non-linear quantization, similar to A-Law and U-Law. AAF supports 2 sample sizes, 8-bit ASCII (1 character), and 16-bit ASCII (2 characters).

The encoder expects Raw Signed 16-bit PCM.

-- File Format --
The AAF Format stores audio in a fixed-format file, the structure of which is as follows:
================================
APERTURE AUDIO FORMAT (c) 1986<lf>
<frequency>,<channels>,<mode>,<file description><lf>
<samples>
================================
Frequency is measured in hz, so 16000 stores 16000 hz data.
Channels is how many channels the audio has, 1 is used for mono and 2 is for stereo.
Mode selects whether the samples are 8-bit Base-95 or 16-bit Base-95, with s being 8-bit and d being 16-bit. (Single/Double)
File Description is unparsed Metadata, such as a name for a sample, or title of a recording.

After the magic string and after the header, linefeeds should follow.
Optionally an additional carriage return can be included for support for standard DOS utilities.

The samples are the raw data, with data being encoded in order of channel number, channel 0 is the first in the pair, then channel 1, if the file is stereo. Support for more channels is possible but currently unused.

The file description field is optional but recommended, and can contain any text data as long as it doesn't contain commas (this marks a new field, but there are no fields after the description field) or newlines (this marks the start of audio data). Double samples are stored big-endian way, with the second character being the least signifigant byte.
The base95 mapping has value 0 corospond to space, and value 94 corospond to ~ (tilde). This means that for any given ASCII code, the offset is a fixed 32.

-- Quantization Mapping --
2-Character AAF has a range of 16 bits, which has low levels of quantization. AAF applies non-linear quantization internally, leading to higher but still relatively low quantization levels.

These quantization schemes are known as R-Law-Big (the 2-Character Encoding) and R-Law-Little (the 1-Character Encoding)
They're named after Aperture Science Programmer Doug Rattmann, whom developed the format.
